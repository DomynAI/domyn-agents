CLI commands

The domyn command is installed with the package (see Installation). Every command accepts -h / --help.

CommandWhat it does
domyn runChat with an agent in the terminal
domyn setupChoose the provider, model and agent of domyn run
domyn initCreate a new project with an example agent
domyn skillsList the skills the configuration loads
domyn skillShow a skill, or stop loading it
domyn exportSave the configuration, with its skills and instructions, into a new folder to share
domyn connectConnect an agent to the Domyn platform as a relay worker

The commands available inside a domyn run session, such as /model or /resume, are listed in Sessions and commands.

Global options​

Given before the command: domyn --log-level DEBUG run.

OptionTypeDefaultDescription
--log-levelstrWARNING for run, setup, init, skills and skill; INFO for the serversLogging level: DEBUG, INFO, WARNING, ERROR, CRITICAL. Any other value is taken as INFO.
--versionPrints the version and exits.

Environment​

Before running any command, domyn reads a .env file from the current directory or the nearest parent directory that has one, then ~/.domyn/credentials, where the setup wizard saves API keys. A variable already set in the environment is never replaced, and .env comes before the credentials file. These variables are what ${VAR} in a YAML configuration refers to. With --project, the project's own credentials file is read first, and ~/.domyn/credentials supplies only the keys the project does not set.

run, setup, skills, skill and export take --project <name> to work on a project, a separate configuration, instead of the default one in ~/.domyn. A name means ~/.domyn/projects/<name>; a value containing / or starting with . or ~ is the path of a project folder.

domyn run​

domyn run [FILE] [MESSAGE] [OPTIONS]

Opens a chat session with an agent. See Sessions and commands for the session itself.

ArgumentDescription
FILEA .py or .yaml file defining the agent. Without it, the agent configured in ~/.domyn/config.yaml; the first time, the setup wizard runs before the session.
MESSAGESent as the first message of the session.

From a Python file, the agent is the one that is not a sub-agent of another; from a YAML file, its entrypoint.

OptionTypeDefaultDescription
--agent-name, -astrThe variable holding the agent, when a Python file defines more than one.
--resumeflagoffContinues a past conversation: --resume <conversation_id>, or --resume alone to choose one from a list. The id takes the place of MESSAGE, so the two cannot be combined. For a conversation started from a file, give the same FILE.
--expand-skillsflagoffGives the model every skill in full up front, instead of an index it reads from on demand. Uses more of the context window.
--skill-sectionsflagoffLists each skill's sections in the index. Uses more of the context window.
--verbose, -vflagoffShows internal events: model calls, hooks, hand-offs.
--no-bannerflagoffSkips the startup banner.
--projectstrRuns a project instead of the default configuration. The banner shows its name.
--voiceflagoffStarts with push-to-talk on, as /voice does: hold the space bar to speak. Needs the audio extra. See Talking instead of typing.

The skills and the standing instructions are those the configuration declares; no option adds or removes any.

When the session ends, it prints the conversation id and the command that resumes it, with FILE when the session was started from one: domyn run agent.yaml --resume <conversation_id>.

domyn setup​

domyn setup [--show] [--project NAME] [--import FOLDER]

Runs the setup wizard: provider, model and API key, standing instructions, built-in tools and skills, saved to ~/.domyn/config.yaml and, for the key, ~/.domyn/credentials. Run again over an existing configuration, it shows each part and asks whether to keep it. See the CLI quickstart and Configuring the CLI.

OptionDescription
--showPrints the active configuration and exits.
--projectSets up a project instead of the default configuration, creating it if it does not exist.
--importCreates a new project from a folder made by domyn export, named after the folder unless --project gives a name. The wizard shows each exported setting and asks whether to keep it; when you do not keep the skills, it also offers the built-in skills the export does not include, unticked. It warns when the export was made by another version of domyn-agents, or does not say which. Cannot be combined with --show.

domyn init​

domyn init [PROJECT_NAME] [--directory DIR] [--force]

Creates a new project with uv: a pyproject.toml that depends on domyn[cli], an example agent.py with two tools, a README.md and a Dockerfile that runs domyn serve agent.py, then installs the dependencies with uv sync. uv must be installed. Without PROJECT_NAME, it asks for one.

OptionTypeDefaultDescription
--directory, -dstr./PROJECT_NAMEWhere to create the project.
--force, -fflagoffDeletes the directory first if it exists and is not empty. Without it, init stops.

Then set the provider in agent.py and run uv run domyn run agent.py.

domyn skills​

domyn skills

Lists the skills the configuration loads, ./.domyn/config.yaml when the current directory has one and ~/.domyn/config.yaml otherwise: their names, descriptions, sections and files, and why any is unavailable. A relative path in the configuration is read from the current directory, as domyn run reads it.

OptionTypeDescription
--projectstrUses a project's configuration.

domyn skill​

domyn skill show|remove NAME

Works on the skills the global ~/.domyn/config.yaml loads, whatever the current directory, or a project's with --project.

ActionDescription
showPrints the skill: its file, its sections and its text. NAME#SECTION prints one ## section.
removeRemoves the entry that names the skill, its folder or its .md file, from the configuration. No file is deleted. A skill loaded through a listed folder, such as ./.domyn/skills, has no entry of its own: nothing is removed, and the command says how to stop loading it.
OptionDescription
--projectUses a project's configuration.

domyn export​

domyn export FOLDER [--config FILE] [--project NAME]

Saves the configuration into the new folder FOLDER, with the skills and standing instructions it uses, so it can be shared or run elsewhere. The folder is a project: run it where it is with domyn run --project FOLDER, move it to ~/.domyn/projects/<name> and run domyn run --project <name>, or create a new project from it with domyn setup --import FOLDER.

OptionTypeDefaultDescription
--configpaththe one domyn run usesThe configuration file to export.
--projectstrExports a project instead of the default configuration.

A skill is copied as its SKILL.md plus the files its external_files lists; anything else in its folder is left out and named in the report. API keys, approvals and conversation history are never copied: a key written in the configuration is replaced by a ${VAR} reference, and the report names the variables to set. FOLDER must not exist, or be empty. The folder also gets a hidden .info file with the version of domyn-agents, the date, the Python version and the platform, which domyn setup --import checks. /export FOLDER does the same from inside a session.

domyn connect​

domyn connect MODULE:SYMBOL --channel-id ID --base-url HOST

Serves an agent or a LangGraph graph on a relay channel, for a DelegateAgent in another application to call. domyn expose is an older name for the same command, still accepted. It needs the platform SDK, which provides the relay's address and headers. See Remote agents for the argument, the relay, and LangGraph graphs.

OptionEnvironment variableTypeDefaultDescription
--channel-idDOMYN_CHANNEL_IDstrChannel to serve.
--space-idDOMYN_SPACE_IDstrSpace the channel belongs to.
--configuration-idDOMYN_CONFIGURATION_IDstrConfiguration of the space to use. Optional.
--base-urlDOMYN_BASE_URLstrRelay host, with an optional port. The relay is reached at wss://<host>/relay/v1/ws, or ws:// for localhost, 127.0.0.1 and ::1.
--targetstrServes several channels from one process. Repeatable; each is channel_id=…,space_id=…,base_url=…,configuration_id=…, where only channel_id is required. space_id and base_url default to --space-id and --base-url; configuration_id defaults to --configuration-id only when the target sets no space_id.
--max-concurrencyint8Turns run at the same time. Beyond that, as many more wait, and further requests are refused.
--platform-tools / --no-platform-toolsflagon when the SDK is installed, else offAdds to the entrypoint agent every tool the platform offers that it does not already declare. --platform-tools without the SDK stops and names the version it needs.
--tool-refresh-intervalfloat0With --platform-tools, looks for new platform tools every this many seconds. 0 never does.

DOMYN_API_KEY must be set; it is sent to the relay in the api-key header.
